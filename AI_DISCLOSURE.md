# AI Disclosure

This project uses generative AI at several levels. Some code, documents, and
configurations in this repository were generated or co-generated by AI tools.

This document exists so that you can make an informed decision about using
this mod — whatever your moral position on generative AI, and whatever your
technical requirements are. If AI involvement of any kind is a dealbreaker for
you, you deserve to know before installing. If it isn't, you deserve to know
that it doesn't mean the project is an unmaintained black box.

## Maintenance

Using AI tools has not distanced me from the codebase. I know how it is
structured, I know how it works, and I am able to maintain it manually if the
tooling I use ever becomes non-viable — too expensive, too unreliable,
ethically unacceptable to me, or simply gone. AI assistance is a productivity
choice, not a dependency I couldn't remove.

Every change that lands in this repository is reviewed and accepted by a
human before it ships.

## How AI is actually used in this project

Not all parts of the project involve AI equally. Here is an honest breakdown,
from least to most AI involvement:

### Project origins (Java era) — mostly human

The project was originally created in Java through a manual process. The
architecture was designed primarily by me, inspired by
[SkinSwapper](https://modrinth.com/mod/skinswapper). A few generic,
boilerplate-style classes were generated by AI; the core design decisions
were not.

### Code — mixed

The code is partly AI-generated and partly hand-written. There is no reliable
line-by-line split, and I won't pretend there is one. What matters for users:
every line, regardless of origin, has been read, tested in-game, and accepted
before release.

### Documentation — AI-assisted

Some documents (README, DEV.md, this file, planning docs) are written with
the help of AI. I try to keep them free of "slop" — the verbose, generic
filler unedited AI output tends to produce — but honestly, I only actively
hunt it down where I think it matters. Treat the docs as practical
references, not polished prose.

### Feature changes — spec-driven AI implementation

New changes to the mod follow a spec-driven workflow using the OpenSpec
framework:

1. A change is first described as **specifications and design documents**
   (what should change, why, and how).
2. I **review and validate these specs** to confirm the change matches my
   intentions and is implemented the way I want it implemented.
3. The implementation itself is **mainly AI-generated**, following the
   approved spec.
4. After implementation, I **review the resulting code** to catch anything
   aberrant — wrong behavior, nonsense code, drift from the spec — before it
   is committed.

### Code reviews — AI-assisted, human-decided

Code reviews may be performed with AI assistance (as a second pair of eyes
on diffs, edge cases, or style). The final call on whether code is acceptable
is always human.

## What this means in practice

- **If you avoid AI-generated content entirely:** this mod is not for you, and
  that's a legitimate choice — now you know.
- **If you care about maintenance risk:** the project has a human maintainer
  who understands every part of it and can work without AI tooling.
- **If you care about code quality:** the quality gate is the same as any
  human-written project — review, testing, and a maintainer who is
  accountable for what ships.
